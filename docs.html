A dashboard for your Valheim server.

I wanted one page my family and friends could pull up to see who's on our server, what day it is in-game, who's played the most and who keeps dying. Longhouse runs next to the dedicated server and builds that page from the server's logs.

Quick start See the live preview

Status: the dashboard, collector and Docker image work with a vanilla server today. The server plugin and companion mod (tiers 1 and 2 below) are in mods/ since 0.2.0; see mods/README.md to install them. The public preview runs on invented mock data.

Features

It works fine on a phone too.

Live server statusOnline state, player count, uptime, version, world day, time of day and weather.
Boss progressionAll seven forsaken, which day each fell and who was there.
Armory-style profilesEach Viking drawn with their hair, beard and gear, surrounded by their equipment slots, plus vitals, food, skills and lifetime stats.
Hall of recordsLeaderboards for kills, deaths, building and distance travelled.
World statsMost-eaten food, materials gathered and creatures slain, filterable by biome.
ActivityA "when we play" heatmap and a live feed of joins, deaths, raids and boss kills.

There's a dark mode, the frontend is plain static files, and there's no tracking or analytics.

Quick start

Longhouse runs as one container on the same machine as your Valheim server. The deploy/ folder has a compose file that adds a read-only Docker proxy (so Longhouse can read the game's logs) and a Cloudflare Tunnel (so your group can reach it without opening any ports).

  1. Copy the deploy folder to your game host 
    git clone https://github.com/MrGuato/valheim-game-dashboard.git
cd valheim-game-dashboard/deploy
cp .env.example .env
  2. Fill in .env

    The defaults work for a container named valheim. Set LONGHOUSE_TIMEZONE, and list the bosses you've beaten in LONGHOUSE_BOSSES (Valheim 1.0 stores the world in a format Longhouse can't read them from).

  3. Start it 
    docker compose up -d
docker compose logs -f longhouse

    The dashboard listens on 127.0.0.1:8080 on the host. On first start it replays the game container's existing logs, so recent sessions and deaths show up straight away.

  4. Point a Cloudflare Tunnel at it

    If cloudflared already runs on the host, add a public hostname to that tunnel in Zero Trust (Networks → Tunnels), for example valheim.yourdomain.com, with service http://localhost:8080. Otherwise create a Docker tunnel, put its token in TUNNEL_TOKEN, point the hostname at http://longhouse:8080, and start with docker compose --profile tunnel up -d.

  5. Lock it to your group

    In Zero Trust, add an Access application for the same hostname with a policy that allows only your group's email addresses. See Keeping it private.

Not using Docker for the game server? Point VALHEIM_LOG_PATH at the server's log file instead and run npm start with Node 20 or newer.

How it works

Valheim keeps most character data (skills, food, lifetime stats) on each player's own machine, not on the server. So Longhouse collects data in three tiers: the more you install, the more the dashboard shows.

Tier 0 · no mods Vanilla

The collector follows the game container's logs, polls the Steam query port (game port + 1, so 2457 by default) and reads the world save. That's enough for online status, who's connected, session lengths, deaths, raids, the activity heatmap, the world day and time, and boss progress. The log lines it matches look like this:

# a player spawned (or respawned)
Got character ZDOID from Astrid : 2084737421:1
# the same line with 0:0 means that player just died
Got character ZDOID from Leif : 0:0

Log formats can change between game updates, so patterns live in one file and are covered by tests.

Tier 1 · server plugin Optional

Available A small BepInEx plugin installed only on the server. It reads what the server already knows about connected players: which biome each player is in (or that they're in a dungeon or asleep), their appearance (body, skin, hair, beard), their visible equipment and their health, which is what the character figures are drawn from. It writes one LH1 {json} line per player to the server log, which the collector already follows. Players don't need to install anything, and it has no effect on their achievements.

Tier 2 · companion mod Opt-in per player

Available Food buffs, skill levels, materials picked up and lifetime stats (kills per creature, crafts, builds, jumps) are stored in each player's character file on their own PC. Players who want them on the dashboard install a lightweight client mod that sends a summary once a minute over the game connection to the server plugin, which logs it under the name of the connection it came from. Anyone who skips it still shows up with Tier 0 and Tier 1 data.

Achievements: Valheim 1.0 turns achievements off while a game is modded, and the BepInEx loader for Valheim marks every modded game that way. So a player running the companion mod (or any BepInEx mod) can't earn achievements until they remove BepInEx. Lifetime stats keep counting either way.

Longhouse never stores chat, IP addresses or exact coordinates. Steam IDs are hashed before they're written to disk and are never sent to the browser.

Keeping it private

The code is public; your server isn't. Longhouse is built so you can publish (or fork) the repo without ever exposing your server address, passwords or your group's data.

What stays out of git

  • Server address and secrets live in .env, which is gitignored. The repo only has .env.example with placeholders.
  • Real data lives in ./data (gitignored). The repo only ships mock data.
  • The address on the page is hidden by default (LONGHOUSE_HIDE_ADDRESS=true) and shows "Address shared privately" instead.
# confirm git is ignoring your secrets before you push
git check-ignore .env data/

Don't host real data on GitHub Pages. Pages sites are public to anyone with the link. Use Pages only for the mock-data preview, and serve your group's dashboard from your own machine.

Snapshot schema

The collector serves one JSON document at /api/snapshot.json, and the dashboard renders it. Writing your own collector (a Discord bot, a different log parser) only means producing this shape. The full example lives in assets/mock-data.js.

snapshot.json (abridged)

{
  "schema": 1,
  "generatedAt": "2026-10-21T19:40:00Z",
  "server": {
    "name": "Odin's Rest", "online": true, "version": "0.220.5",
    "players": { "online": 4, "max": 10 },
    "worldDay": 412, "timeOfDay": "Evening", "weather": "Mist",
    "address": null
  },
  "bosses": [ { "id": "eikthyr", "defeated": true, "day": 9, "by": ["Astrid"] } ],
  "players": [ {
    "name": "Astrid", "online": true, "biome": "mistlands",
    "vitals": { "hp": [198, 232], "stamina": [141, 166], "eitr": [40, 64] },
    "foods": [ { "name": "Seeker aspic", "minutesLeft": 31, "total": 45, "kind": "eitr" } ],
    "equipment": { "weapon": { "name": "Mistwalker", "q": 3 } },
    "skills": [ ["Swords", 74] ],
    "stats": { "kills": 4812, "deaths": 37, "built": 2140 }
  } ],
  "foods":     [ ["Lox meat pie", 812] ],
  "materials": [ ["Wood", 48210, "meadows"] ],
  "mobs":      [ ["Greydwarf", 3104, "blackforest"] ],
  "heatmap":   [ [0, 0, 1, …] ],   // 7 days × 24 hours, avg players
  "activity":  [ { "m": 6, "type": "join", "text": "**Sigrid** joined the server" } ]
}

Fields that a tier doesn't provide are left out. Biome ids are meadows, blackforest, swamp, mountain, plains, mistlands, ashlands, deepnorth and ocean. Activity text supports **bold** only; everything else is escaped.

Customizing

Colors and theme

All colors are CSS custom properties at the top of assets/styles.css. Change --accent to re-skin buttons, bars and highlights; biome colors are the --b-* tokens. Light is the default. Visitors can switch to dark with the moon button, and the choice is remembered in their browser.

Panels

Every panel is rendered by its own function in assets/dashboard.js (renderBosses, renderLeaders, and so on) and hides itself when the snapshot has no data for it. Adding one means one function and one container in index.html.

Character figures

Figures are drawn by assets/figure.js from a player's appearance (body type, skin, hair, beard) and equipment. Armor colors are matched by keywords in the item name, so new gear sets only need a line in its MATERIALS table.

Local development

There's no build step and no npm dependencies. To work on the dashboard with mock data, serve the folder with any static server:

python -m http.server 5178

To run the real collector against a log file, use Node 20 or newer:

VALHEIM_LOG_PATH=./valheim.log LONGHOUSE_DATA_DIR=./data npm start

The page uses api/snapshot.json when the collector serves it and falls back to assets/mock-data.js everywhere else. Run the tests with npm test.

FAQ

Do I need mods?

No. Without mods you get status, who's online, sessions, deaths, raids and the heatmap. Gear and world details need the server plugin; food, skills and per-creature kills need the companion mod.

Why drawn figures instead of the real 3D models?

Valheim's character models are game assets that can't be redistributed, and there's no public model viewer for them the way there is for some other games. Longhouse draws its own figures from the same appearance and gear data instead. A later companion mod could render each player's actual in-game character to an image and upload it.

Does it work with crossplay servers?

Log-based features work either way. Crossplay servers may not answer Steam queries, in which case online status and player count fall back to the log.

Will it slow down my server?

It shouldn't. The collector reads the log as it's written and sends one small query every refresh interval. The server plugin only reads state the server already has.

Can players fake their stats?

Companion data is self-reported, so a determined player could inflate their own numbers. They can't post as someone else: the name comes from the game connection the stats arrive on, and the collector clamps every value. For a group of friends that's usually plenty, and AcceptCompanionStats = false on the server turns it off.

Does it run on Windows?

Yes, through Docker Desktop. A standalone build without Docker is on the roadmap.

Is this affiliated with Valheim?

No, it's just a side project. Not affiliated with Iron Gate or Coffee Stain.

Contributing

Issues and PRs are welcome. A couple of things to keep in mind:

  • Never commit a real server address, password, token or player data. Use the mock snapshot for screenshots.
  • Keep the frontend dependency-free so it can be served from anywhere.
  • Log patterns and the snapshot schema are public contracts. Changes to either need a test and a note in the changelog.
